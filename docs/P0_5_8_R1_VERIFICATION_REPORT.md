## 三、生克制化原典语义审计

### 原典
> "生克制化，须制中有生，生中有制。太过者宜损之，不及者宜益之。"

### 当前实现逻辑
```python
# 检查"制中有生"
for k_src, k_dst in keeps_pairs:
    for g_src, g_dst in gen_pairs:
        if g_dst == k_dst:  # 被克者有生化
            gen_in_keeps.append((g_src, k_src, k_dst))

# 检查"生中有制"
for g_src, g_dst in gen_pairs:
    for k_src, k_dst in keeps_pairs:
        if k_dst == g_src:  # 生者有克制
            keeps_in_gen.append((k_src, g_src, g_dst))
```

### 语义验证

#### ✅ 已验证部分
1. **"制中有生"**
   - 实现：被克的五行（k_dst），有另一五行生它（g_src → g_dst = k_dst）
   - 示例：WOOD→EARTH（克），同时 WATER→WOOD→EARTH（生中有通关）
   - 符合原典语义

2. **"生中有制"**
   - 实现：生的五行（g_src），有另一五行克它（k_dst = g_src）
   - 示例：WOOD→FIRE（生），同时 METAL→WOOD→FIRE（生中有制约）
   - 符合原典语义

#### ⚠️ 未验证部分
1. **"太过者宜损之，不及者宜益之"**
   - 当前实现：未检查
   - 状态：SEMANTIC_ONLY / UNRESOLVED
   - 原因：需要先定义"太过""不及"的确定性标准

2. **"须"的语义强度**
   - 原典："须制中有生，生中有制"
   - 当前实现：只要存在任意一条制中有生 或 生中有制 的关系链就成立
   - 问题：是否要求"所有"制都有生、"所有"生都有制？
   - 状态：需要进一步语义审计

3. **关系链的完整度**
   - 当前实现：只检查是否存在关系链
   - 问题：是否需要检查关系链的"强度"或"数量"？
   - 状态：不确定，保持 CURRENT IMPLEMENTATION
