## 一、同词异义审计结论（实证）

### 1.1 「印旺」六部语义全量实证（最典型同词异义）

| 引擎 | 出处 | 原文证据 | 语义 | state_domain |
|---|---|---|---|---|
| DTS 滴天髓 | DTS-033-015「印綬太旺，日主無着落」；DTS-045-001「母慈滅子關頭異」 | 印过旺→生多为克、日主无着落，**为病** | 过旺致害（母慈灭子） | CONDITION_STATE |
| PZZQ 子平真诠 | PZZQ-007-001「身強印旺透煞，孤貧…身旺不勞印生」；PZZQ-007-022「身弱逢之，最喜印旺」 | 印旺喜忌**随身强弱**：身弱喜印旺、身强印旺反孤贫 | 格局平衡（喜忌依赖身强弱） | CONDITION_STATE |
| QTBJ 穷通宝鉴 | QTBJ-040-001「得印旺殺高大富大貴」；QTBJ-049-001「兩透印旺殺高出將入相」 | 印旺杀高=调候组合，**为贵征** | 调候结构条件 | CONDITION_STATE |
| SFTK 神峰通考 | SFTK-022-010「印旺遇財乃發」；SFTK-121-001「印旺財伏」 | 印旺=病（雕枯旺弱之旺），**需财为药** | 病（药=财） | CONDITION_STATE |
| SMTH 三命通会 | SMTH-072-009「亥卯未印旺俱可言貴」；SMTH-052-002「女命印旺官輕，夫權在手」 | 三合局印旺=结构旺，可论贵；女命断语 | 季节/三合结构旺 | CONDITION_STATE |
| YHZP 渊海子平 | YHZP-138-001「身旺印多，喜行財地」；YHZP-131-001「身旺印旺，破財不聚」 | 身旺印旺需财破印，**喜行财地** | 基础旺衰（喜财） | CONDITION_STATE |

**结论**：同词「印旺」，六部语义各自独立——DTS 病态 / PZZQ 平衡 / QTBJ 调候 / SFTK 病药 / SMTH 结构 / YHZP 喜财。**不得合并为统一「印旺」布尔或枚举。**

### 1.3 「母慈滅子」归属

仅 DTS-045-001「母慈滅子關頭異，夫健何為又怕妻」（反局篇）——**DTS 专属概念**，不扩散到其他引擎。对应规则开发时 concept_id 必须绑定 DTS。

- **清濁**：DTS 一清到底/满盘浊气 / PZZQ 格清格浊 / SFTK 去浊留清——需审计
- **化神**：DTS 化象（真化条件）/ SFTK 化神（从化）——需审计
- **從格**：DTS「從象」/ SFTK·SMTH·YHZP「從格」——异词近义，需审计

## 二、Concept 隔离机制设计（提案，待审批）

### 2.1 新注册表 `governance/concept_registry.json`

每条 concept 记录（PATCH-001 §12 字段落地）：

```json
{
  "concept_id": "CONCEPT-PZZQ-YIN_WANG",
  "book": "子平真诠",
  "engine": "ZIPIN_ZHENQUAN",
  "concept": "印旺",
  "semantic_domain": "印格平衡",
  "state_domain": "CONDITION_STATE",
  "definition": "印旺随身强弱而喜忌不同：身弱喜印旺（生身为用）；身强印旺反孤贫（身旺不劳印生）",
  "source_ids": ["PZZQ-007-001", "PZZQ-007-022", "PZZQ-007-023"],
  "rule_ids": [],
  "text_evidence": "「身旺不勞印生，印旺何勞煞助」「身弱逢之，最喜印旺」",
  "status": "PENDING"
}
```

字段铁律：
- `concept_id` = `CONCEPT-<BOOK>-<CONCEPT>`（book 用英文短名：YHZP/PZZQ/DTS/QTBJ/SMTH/SFTK）
- `semantic_domain`：该书该概念的语义域（如印格平衡/调候结构/病药/过旺致害）
- `state_domain`：复用 PATCH-001 domain 分类（CONDITION/STRENGTH/EFFECT/...）
- `source_ids`：必须全部绑定（证据链铁律）
- `rule_ids`：规则审批后回填
- `status`：PENDING → APPROVED（Human 审批）

### 2.2 引擎执行约束

1. **规则字段**：任何 `field` 引用派生概念（非 L0 基础字段）时，规则必须带 `concept_id` 注解，标注该书语义域；未注解 → FAIL_CLOSED
2. **同一字段名跨书**：允许同名（如 `strength_state`），但由 concept_id 区分语义域，禁止跨书共享值域语义
3. **规则开发顺序**（Human 拍板）：先隔离机制审批 → 再按「印系（印轻/印旺/母慈灭子）」开发规则 → 逐条绑定 source → 审批

### 2.3 与现有体系的衔接

- L0 基础字段（day_stem/month_branch/ten_god 等）跨书共享 = 正常（同一八字输入），不需要 concept 隔离
- 派生枚举（dts_*/pzzq_* 等）已按引擎前缀隔离（PATCH-001 完成）——concept_registry 是**语义层**再隔离
- `dts_pattern`/`pzzq_formation_state` 等格局枚举保持引擎前缀，concept_id 只加语义注解
