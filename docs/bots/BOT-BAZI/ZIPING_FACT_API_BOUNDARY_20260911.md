# ZIPING Fact API 边界裁决：流年 / 流月 / 流日属于「时间干支事实层」

- 日期：2026-09-11
- 状态：**架构裁决已定（User 终裁），待排期实现**
- 适用范围：顺天 ZIPING（子平）引擎 —— 八字排盘 / 时间事实层 / 命理分析层边界
- 性质：架构决策记录（ADR）。本文件只固化边界与 Fact API 契约，**不含实现代码**

---

## 0. 一句话裁决

流年、流月、流日在八字排盘输出中，必须输出**可计算、可验证的时间干支事实数据（Fact Data）**，
**不是**辩证后的命理结论（Judgment）。

> 排盘引擎负责生产「干支时间轴」（时间坐标），分析引擎负责「解释时间轴」（吉凶论断）。

这与项目既有审计原则一致：**先冻结事实层（Fact，不同算法必须一致），再允许不同命理模型在其上做解释（Judgment，允许流派差异）。**

---

## 1. Fact 与 Judgment 的二分原则

| 维度 | Fact（事实） | Judgment（判断） |
|---|---|---|
| 可验证性 | 机器可验证、可复算，不同算法结果必须一致 | 不同流派可不同，属于模型 |
| 例子 | 2026 = 丙午；2026 年寅月 = 庚寅；2026-03-15 = 戊申日 | 丙午年对丙日主：身旺/身弱？喜火/忌火？ |
| 产出层 | 八字排盘 / 时间运算事实层 | 命理分析引擎（旺衰/格局/喜忌/财官/婚姻/流年事件） |
| 是否给吉凶 | **否**，只给干支与时间区间 | 是，允许结论性表述 |

**禁止越界**：时间事实层不得输出「2026 事业上涨 / 财运不好 / 有贵人」之类结论；这类内容只能出现在分析层。

---

## 2. 排盘引擎应输出的 Fact API 契约（原样固化）

以 原局 `庚申 壬午 丙寅 癸巳`、进入 2026 年为例。

### 2.1 大运（Decade Luck）—— Fact
```json
{ "type": "大运", "pillar": "戊午", "start": "2018-06-01", "end": "2028-06-01" }
```
字段：`type / pillar / start / end`（每步大运的**公历起止区间**，10 年一步）。

### 2.2 流年（Annual Pillar）—— Fact
```json
{ "year": 2026, "pillar": "丙午", "gan": "丙", "zhi": "午", "start": "2026-02-04", "end": "2027-02-03" }
```
字段：`year / pillar / gan / zhi / start / end`。
- **年柱以立春切换**（不是公历 1 月 1 日）：2026 流年区间 = 2026 立春 → 2027 立春前一日。
- 示例已核验：2026 = **丙午**（天干 (2026−4) mod 10 = 丙；地支 (2026−4) mod 12 = 午）。

### 2.3 流月（Monthly Pillar）—— Fact
```json
{ "type": "流月", "year": 2026, "month_index": 1, "pillar": "庚寅", "start": "2026-02-04", "end": "2026-03-05" }
```
字段：`type / year / month_index / pillar / gan / zhi / start / end`。
- **流月以节气月切换**，`month_index=1` 为**寅月**（立春起，非公历 1 月）；寅月 立春→惊蛰前一日。
- 月干由五虎遁按年干推：示例 丙年寅月 = **庚寅**（丙辛之岁寻庚寅），已核验。
- 必须带每节的精确起止（节气边界）。

### 2.4 流日（Daily Pillar）—— Fact
```json
{ "type": "流日", "date": "2026-05-20", "pillar": "甲辰", "gan": "甲", "zhi": "辰" }
```
字段：`type / date / pillar / gan / zhi`。

### 2.5 明确禁止出现在 Fact 层的内容（属分析层）
- ❌「这个月适合投资 / 容易破财」
- ❌「2026 事业上涨 / 财运不好 / 有贵人」

### 2.6 分析层（Interpretation Layer）的产物形态（对照，不属于排盘）
输入：原局 `庚申 壬午 丙寅 癸巳` + 大运 `戊午` + 流年 `丙午`，分析引擎才产出：
```json
{ "analysis": { "career": "官杀作用明显", "wealth": "财星受制", "risk": "投资风险增加" } }
```

## 3. 正确的数据流（分层）

```
出生输入
  ↓ TimeResolver（真太阳时 / 经度 / 均时差 / 23:00 换日）
  ↓ 四柱计算（年/月/日/时，节气边界）
  ↓ 基础事实层（藏干 / 十神 / 五行阴阳 / 空亡 / 长生 / 干支关系 …）
  ↓ 大运 / 流年 / 流月 / 流日 计算
  ↓ —— 时间事实层（Fact，干支时间轴，输出给所有引擎消费）====================
  ↓ 命理分析引擎（Judgment）
      ├─ 旺衰  ├─ 格局  ├─ 喜忌
      ├─ 财官分析 ├─ 婚姻分析 └─ 流年事件判断
```

下游消费方（择日引擎、事件验证引擎等）统一消费时间事实层的干支时间轴。

## 4. 目录结构调整裁决

### A. 时间运算事实层（对所有引擎输出，纯 Fact）
```
08 时间周期事实
  ├─ 起运点
  ├─ 顺逆规则
  ├─ 大运柱
  ├─ 大运起止
  ├─ 流年干支
  ├─ 流月干支
  └─ 流日干支
```

### B. 命理分析层（Judgment，单独成层）
```
09 岁运分析
  ├─ 大运作用
  ├─ 流年作用
  ├─ 流月作用
  ├─ 吉凶判断
  └─ 事件映射
```

> 原「08 时间运程」把「起运/顺逆/大运/流年/流月」与作用分析混在一起，按上述拆为 **08 事实** 与 **09 分析** 两层。

## 5. 现状 vs 目标 Fact API（2026-09-11 代码核查事实）

| Fact 能力 | 目标契约 | 现状（代码核查） | 差距 |
|---|---|---|---|
| 大运柱 | pillar | `BaziChart.luck_pillars` 10 步，干支+十神 ✅ | 缺 **每步 start/end 公历起止**；仅有一个浮点 `start_age`（起运岁数），未展开成区间 |
| 起运点/顺逆 | — | `start_age` + 年干阴阳×性别定顺逆 ✅（已秒级验证） | 基本具备，需把起运点换算为公历日期锚点 |
| 流年干支 | year/pillar/gan/zhi/start/end，**立春切换** | 八字引擎 `BaziChart` **不输出**；河洛 `heluo/time_sequence.compute_liu_nian` 仅返回单个干支字符串，**无 gan/zhi 拆分、无立春起止**，且耦合 gender/六爻 | 需在八字时间事实层新建：干支拆分 + 立春区间 |
| 流月干支 | month_index(寅=1)/pillar/gan/zhi/start/end，**节气切换** | 河洛 `compute_liu_yue` 按**公历月序号**推、仅干支字符串，**非节气月、无起止** | 需按节气月重建（五虎遁 + 12 节精确边界） |
| 流日干支 | date/pillar/gan/zhi | 河洛 `compute_liu_ri` 仅干支字符串；八字 sxtwl 底层 `getDayGZ` 具备能力但未封装为时间轴接口 | 需封装：任意日期 → 日干支（gan/zhi 拆分） |
| 分析层隔离 | Fact 层不得出吉凶 | 子平 `judgment`（旺衰/格局/用神）已是独立层，方向一致 ✅ | 新增时间事实时保持不越界 |

**底层可行性**：sxtwl 已能取任意日干支与节气精确时刻（现引擎节气定月、起运秒级计算已在用），
因此流年/流月/流日**不需要新命理事实，只缺「干支时间轴」的封装与 start/end 区间计算**。

**注意**：河洛 `timeline_yun / time_sequence` 的流年流月流日是**河洛体系**（耦合六爻/元堂/gender、按公历月），
不可直接复用为子平 Fact；子平时间事实层应基于八字自身的 sxtwl 节气口径独立实现，避免体系串味。

---

## 6. 验收口径（实现时的机器可验证锚点）

1. 同一时间点，流年/流月/流日干支在任何调用路径下**完全一致**（Fact 唯一性）。
2. 流年严格以立春为界、流月严格以 12 节为界，边界精确到节气时刻（与现引擎年月柱切换同一套口径）。
3. Fact 输出只含 `type/pillar/gan/zhi/start/end/date/year/month_index` 等时间字段，**零吉凶词汇**。
4. 分析层只能消费 Fact，不得自行重算干支（沿用「ZiPing 不得重新计算 BAZI 事实」同一原则）。
