## 一、确诊的 BUG（案例批量测试暴露）

### BUG-1（根因）：宾主归因未被效率判定消费

- **现象**：51 个案例 `work_efficiency` 全部输出 `MEDIUM / PARTIALLY_CLEAR / MEDIUM_NOBLE`，零区分度。巨富 C01（辰库收水）与反例 C08（仓库保管员，"劫财合官非我所有"）**同档**。
- **根因**：`_analyze_zuogong` 的 detail 字符串里已有 `[主位]/[宾位]/[主取宾]/[宾做功]` 标记（V2.3 就埋了），但 `_resolve_work_efficiency` **完全不消费**——只看 `len(methods)` 和字符串含"制/合/化/生/开/收/包"。
- **后果**：C08 的"GENG(劫财)合BING(正官)…[宾做功]"（宾位合走，非我所有）被计为有效做功 → 与巨富同档。
- **文献依据**：案例集原文"有财官≠有富贵，关键在于**谁在做功**"；"主位做功=为我所用，宾位做功=非我所有"。

### BUG-2：力量集中判据写反

- **现象**：`eff_power_concentrated = len(methods) <= 1`——把"做功力量是否集中"实现成"做功方法数量少"。
- **后果**：任何盘都有多个方法 → 恒 `False` → **LARGE 分支永远不可达**；而原书"大效率"（单闭环/多力聚歼一对象/闭库收物）恰恰是集中形态。
- **文献依据**：原书案例1"辰库收水"：一个辰收满盘水=**收的力量极大**（力量集中）。正确判据=**目标集中（目标支≤1）或单体吸收结构（闭库收物/冲开墓库/包局/势做功=一器收多）**。

### BUG-3：包局判据过松（案例核证发现）

- **现象**：原判据"≥2 支同气包围异气支且在日时"——C08（申酉 2 支围未=比劫围库，争财之象）被误判包局得权；D23（午被误判为土→戌午戌假 3 土）、D22、D43 同病。
- **根因①**：`STEM_ELEMENT[b]` 用**天干五行映射查地支**——地支午（WU=火）撞上天干戊（WU=土）→ 午被误判为土。
- **根因②**：包围支数下限 2 太松，且未检查"被包围者是否含用"。
- **修复**：支五行一律 `_branch_element()`；同气支 **≥3**（原书"三重寅木"起算）且被包围者含财官印（体强包用）才判包局。陈济棠三寅包子 ✓ 保留；C08 申酉 2 支 ✗ 排除。

### BUG-4：冲库归因方向颠倒（案例核证发现）

- **现象**：C05（丑未冲开库制杀取财·亿万富翁）的"冲开墓库"因丑在宾位被标 INEFFECTIVE——但文献"以**我宫**未土杀库，冲制**宾位**丑土财库"=主位主动冲开宾库=**主取宾，应为 EFFECTIVE**。
- **修复**：归因看**冲者**位置（冲者主位=主冲宾=EFFECTIVE），不再只看被冲库位。

### BUG-5：吸收结构假阳性（案例核证发现）

- **现象**：D25（火土有势无大功·下岗工薪族）的"闭库收FIRE[宾位]"（戌收火=他人收物）被算作吸收结构 → 集中=True → 误判 LARGE。
- **修复**：`absorb_structure` 只检查 **EFFECTIVE 归因**的方法对应 detail；宾位收物不算集中。

### BUG-6：印制食伤取对顺序（案例核证发现）

- **现象**：`break` 只取第一对（可能宾位），C07 申中庚制未中乙（宾位）优先于巳中庚制未中乙（主位）。
- **修复**：收集全部配对后**主位印优先**排序取对。

## 二、修复内容（引擎实现）

### 2.1 新增：做功归因层 `zuo_gong_attributions`

- `BlindBaziResult` 新增 `zuo_gong_attributions: List[str]`（与 `zuo_gong_detail` 一一对应），`to_dict()` 输出。
- 新增常量 `ZuoGongAttribution`：`EFFECTIVE`（主位得气·为我所用）/ `INEFFECTIVE`（宾位做功·非我所有）/ `NEGATIVE`（负功·禄神受穿）/ `NEUTRAL`。
- 每个做功方法生成处同步归因：
  - 合/穿/刑/制/生：体在主位 → EFFECTIVE，体在宾位 → INEFFECTIVE
  - 财制印/官杀制比劫/财制比劫（用克体）：主位任一参与 → EFFECTIVE
  - 地支三合：局中有主位支 → EFFECTIVE
  - 墓库：闭库收物主位收 → EFFECTIVE；冲库看冲者位置（主冲宾 → EFFECTIVE）
  - 暗合：主位参与（资源整合）→ EFFECTIVE，宾位间（暗藏信息）→ INEFFECTIVE
  - 包局：体强包用（≥3 支+被包围含财官印）→ EFFECTIVE
  - 印制食伤：主位印优先 → EFFECTIVE
  - 食伤泄秀：日主自身泄气 → EFFECTIVE
  - 势做功：势中有主位支 → EFFECTIVE
  - 禄神受穿：日主禄受损 → **NEGATIVE**（负功）

### 2.2 重构 `_resolve_work_efficiency`（消费归因）

```
if not methods                        → NONE / CHAOTIC / POOR（无做功=贫贱）
if not effective_methods              → NONE / CHAOTIC / POOR（全宾位做功=他作嫁）
else:
  判据① 路径直接 = True（距离≤2 已过滤）
  判据② 力量集中 = 目标支≤1 或 主位吸收结构（闭库收/冲开/包局/势做功）
  判据③ 对象得力 = 有效方法含 制/开/收/包（得手）；仅合/化/生=弱
  三判据全中 → LARGE / CLEAR / LARGE_NOBLE
  路径直接+(集中或得力) → MEDIUM / PARTIALLY_CLEAR / MEDIUM_NOBLE
  路径直接+仅弱得手   → SMALL / MIXED / SMALL_NOBLE
  其余               → NONE / CHAOTIC / POOR
```

全部结构判定、零数字化（BLIND-ARCH-006 / BLIND-G16）。

## 五、遗留域缺口（本轮不硬凑，按文献另立核证项）

1. **燥土脆金**（C07）：未戌脆申酉——"财制印"在盲派含燥土脆金形式（土生金反脆），当前引擎只匹配五行正克（丁火克庚金）。需新增 VERIFY-BLIND 核证项后施工。
2. **合绊/反局**（D28 牢狱）：伤官制官见财、三合互绊=合多为绊、勾陈包局——"做负功者凶"的负功体系（当前仅禄神受穿=NEGATIVE）。
3. **势做功目标虚实**（D25 类）：势制对象须真支存在（当前已通过 `_branch_element` 修正避免假阳性，但"有势无大功"（势制不透/制不尽）需接 control_completeness 制尽判据）。
4. **伤官当财换象**（D14）：金水伤官不见财官→伤官当财富看（VERIFY-BLIND-022 延伸）。
5. **六亲计数域**（D02-D11）：比肩为兄弟/纳音计数/身旺无官食伤为同胞——引擎未实现，单列二期。
