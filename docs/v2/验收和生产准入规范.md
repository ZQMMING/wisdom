# 01. 最高验收原则

顺天必须永久遵守：

> **跑通全绿，不代表验收成功。**

必须严格区分：

```text
TEST PASS
    ≠
CALCULATION VALIDATED
    ≠
PRODUCTION VALIDATED
    ≠
PRODUCTION ADMITTED
```

例如：

```text
15 passed
8 skipped
```

绝对不能自动得出：

```text
PASS
```

特别是：

```text
Unexpected SKIP > 0
```

时，不能直接宣布：

```text
BASIC_VALIDATED
```

# 21. E6 — Cross-Version Regression

任何算法：

```text

 ↓
v2
```

都必须 Replay 全部 Golden Case。

结果出现差异时必须分类：

```text
EXPECTED_CHANGE
```

或：

```text
REGRESSION
```

禁止：

> “新版本结果不同，所以新版本就是对的。”

任何 Expected Change 必须：

```text
说明原因
更新证据
更新版本
更新 Golden
记录裁决
```

# 25. E10 — Acceptance

E10 是一次验收活动的判定结果。

允许四种：

```text
PASS
CONDITIONAL
FAIL
BLOCKED
```

含义：

### PASS

本次验收全部满足要求。

### CONDITIONAL

存在明确限制，但尚未达到完整生产准入。

### FAIL

存在明确验收失败。

### BLOCKED

因为依赖、证据、基础设施等原因无法完成有效验收。

---

# 26. E10 与生命周期状态的区别

必须严格区分：

```text
E10 Decision
=
PASS / CONDITIONAL / FAIL / BLOCKED
```

和：

```text
Lifecycle Status
=
BASIC_VALIDATED
PRODUCTION_VALIDATED
PRODUCTION_ADMITTED
```

例如：

```text
E10 = PASS
```

并不自动等于：

```text
PRODUCTION_ADMITTED
```

---

# 27. Level 3 — Full Historical Replay

全量历史 Replay 是生产准入阶段的硬门槛。

正确顺序：

```text
基础验收
 ↓
PASS
 ↓
Full Golden / Historical Replay
 ↓
Production Validation
 ↓
Independent Audit
 ↓
Production Admission
```

因此：

> **基础验收不要求一开始就跑完全部历史案例。**

但是：

> **生产准入之前，原则上必须完成全部要求的历史案例 Replay。**

---

# 28. 为什么不能要求第一阶段全量 Replay

如果历史案例数量巨大：

```text
基础验收
 ↓
必须先跑完全部历史案例
```

会导致：

```text
基础 Engine 无法快速验证
```

因此采用：

```text
Level 1
基础 Golden Set
```

先证明基础正确性。

再：

```text
Level 3
Historical Replay
```

证明生产级稳定性。

# 33. “全部案例通过”不等于“所有体系答案相同”

这是顺天最重要的验收原则之一。

例如：

```text
同一个 Canonical Birth State
             ↓
       ┌─────┼─────┐
       ↓     ↓     ↓
      子平   盲派   紫微
       ↓     ↓     ↓
       A      B      C
```

A、B、C 可以不同。

因为：

> **互补不比较。**

验收检查：

```text
计算是否正确
证据是否正确
规则是否属于该体系
派别是否隔离
推导是否可追踪
```

而不是：

```text
子平说财好
 ↓
紫微也必须说财好
```

后者不是验收标准。

---

# 34. Cross-Engine Contamination Test

这是生产级硬门槛。

例如修改：

```text
ZiPing
```

必须证明：

```text
ZiWei Chart
不变

HeLuo Calculation
不变

MangPai Calculation
不变

MeiHua Calculation
不变
```

反过来也一样。

必须建立：

```text
Engine A Change
 ↓
Engine A Result Changes
 ↓
Other Engine Results
Remain Identical
```

如果其他 Engine 非预期变化：

> **FAIL**

---

# 35. Engine Independence

每个 Engine 必须保持：

```text
Calculation
Evidence
Rules
Golden
Regression
Provenance
```

独立。

一个 Engine 的 PASS：

> 不代表另一个 Engine PASS。

一个 Engine 的 FAIL：

> 不能由其他 Engine 的结果替代。

---

# 36. Calculation Freeze

Engine 达到：

```text
CALCULATION_VALIDATED
```

后，核心计算必须进入 Freeze。

任何修改：

```text
Calculation
Algorithm
Calendar
Mapping
Rule
```

必须：

```text
新版本
+
Regression
+
Golden Replay
+
Audit
```

不能：

```text
直接改
```

---

# 37. Determinism

同一输入、同一版本、同一配置必须：

```text
Input
 ↓
Calculation
```

得到：

```text
Same Result
```

即：

```text
same input
+
same version
+
same configuration
=
same calculation
```

# 62. 最终裁决规则

以后任何 Agent 都必须遵守：

> **没有独立验收，不得宣称 Engine 完成。**

> **没有 Canonical State 验证，不得宣称下游 Engine 正式成立。**

> **没有 Golden 100% Execute，不得 BASIC_VALIDATED。**

> **存在 Unexpected Skip，不得直接 PASS。**

> **没有 Full Historical Replay，不得 PRODUCTION_VALIDATED。**

> **没有 Independent Audit，不得 PRODUCTION_ADMITTED。**

> **P0 > 0，不得生产准入。**

> **P1 > 0，未经正式豁免不得生产准入。**

> **不同体系结果不同，不等于错误。**

> **跨体系污染才是必须阻止的错误。**

> **原始 Calculation 永远不能被人工裁决覆盖。**
