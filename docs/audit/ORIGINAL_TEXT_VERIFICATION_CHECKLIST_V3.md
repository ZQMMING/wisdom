## 三层分类体系

### A类：明确条件判断
```
格式："若A，则B" / "A则B" / "A者B也"
性质：明确的逻辑判断，有输入和输出关系
示例："五阳从气不从势"
处理：需二次验证可计算性后才能进入Primitive提取
```

### B类：描述/原则/建议
```
格式："A宜B" / "A喜B" / "A忌B" / "A者B之象"
性质：描述性或建议性陈述
示例："旺则宜泄宜伤"
处理：只能形成Evidence/GuidanceAtom/Research，不能升级为A类
```

### C类：方法论/属性/定义
```
格式："欲识X，先观Y" / "X者Y也" / "所谓X者..."
性质：认识论、定义性陈述、方法论指导
示例："欲识三元万法宗，先观帝载与神功"
处理：只能形成Framework/Methodology，不能进入Production
```

## 可计算性验证（A类二次验证）

即使归类为A类，还需验证：

### 验证1：是否有明确输入
- [ ] 原典是否给出明确的判断对象（如"五阳"、"甲木"）
- [ ] 原典是否给出明确的判断条件（如"生于春"、"阳气盛"）

### 验证2：是否有明确输出
- [ ] 原典是否给出明确的判断结果（如"从气"、"气旺"）
- [ ] 判断结果是否可被Canonical State确定表达

### 验证3：是否可被工程化
- [ ] Canonical State是否能够提供判断所需的所有输入
- [ ] 判断逻辑是否不涉及未完成的算法（如L4力量计算）
- [ ] 是否涉及复杂的状态依赖（如时辰先后、山川异同）

**只有同时通过三个验证的A类，才能进入Step 2 Primitive提取。**

## 文本分层规范

### 分层要求
每条Evidence必须明确标注：

```
text_layer: "ORIGINAL_TEXT" | "ORIGINAL_COMMENTARY" | "LATER_COMMENTARY"
```

### 定义

#### ORIGINAL_TEXT（原文）
- 《滴天髓》正文诗句/歌诀
- 作者：京图（传）
- 特征：四言、五言、七言诗句

#### ORIGINAL_COMMENTARY（任注）
- 任铁樵注释
- 特征：对原文的解释、举例、阐微
- 位置：原注、任氏曰

#### LATER_COMMENTARY（后世注）
- 飞宏、京图后人等后世解释
- 特征：白话翻译、现代解读
- 位置：飞宏曰、现代译者注

### 禁止事项
❌ 禁止将任注当作原文使用  
❌ 禁止将后世解释混入Evidence  
❌ 禁止不加标注混用不同文本层

## 核验流程（v3.0）

```
原典原文 → 语义单元 → Primitive → A/B/C分类 → 可计算性验证 → Condition → Judgment
   ↓          ↓          ↓         ↓            ↓            ↓         ↓
权威来源   提取关键概念 术语对齐   三层分类     二次验证      验证       边界验证
           （禁止混用） （区分A/B/C）（仅A且通过验证）
```

## 核验清单

### 1. 原文核验

#### 1.1 来源权威性
- [ ] 使用通行本权威来源（任铁樵《滴天髓阐微》）
- [ ] 标注来源URL或书籍版本
- [ ] 至少有两个独立来源交叉验证

#### 1.2 原文完整性
- [ ] 提取完整段落（非断章取义）
- [ ] 标注章节位置（如"通神论·天干篇"）
- [ ] 包含任铁樵注释（如有）

#### 1.3 文本分层标注
- [ ] 区分：原文 / 任注 / 后世解释
- [ ] 标注：ORIGINAL_TEXT / ORIGINAL_COMMENTARY / LATER_COMMENTARY
- [ ] 禁止将后世解释当作原文使用

---

### 2. 语义单元提取

#### 2.1 术语来源
- [ ] 每个Primitive术语必须有原典出处
- [ ] 标注术语在原文中的具体位置
- [ ] 禁止使用现代工程术语替代原典术语

#### 2.2 术语对齐
- [ ] Primitive术语与原典术语一致
- [ ] 禁止混用不同体系术语
- [ ] 禁止将"旺衰"概念等同于"格局"概念

---

### 3. A/B/C分类验证

#### 3.1 分类识别
- [ ] 正确识别A/B/C三类
- [ ] C类明确标注为"方法论/属性/定义"
- [ ] 禁止将C类误认为A类

#### 3.2 分类结果
- [ ] A类：进入可计算性验证
- [ ] B类：只能形成Evidence/Guidance
- [ ] C类：只能形成Framework/Methodology

---

### 4. 可计算性验证（A类专属）

#### 4.1 输入明确性
- [ ] 原典是否给出明确的判断对象
- [ ] 原典是否给出明确的判断条件

#### 4.2 输出明确性
- [ ] 原典是否给出明确的判断结果
- [ ] 判断结果是否可被Canonical State确定表达

#### 4.3 工程可行性
- [ ] Canonical State是否能够提供判断所需的所有输入
- [ ] 判断逻辑是否不涉及未完成的算法
- [ ] 是否涉及复杂的状态依赖

**通过三项验证：✅ 可进入Step 2**  
**未通过任一验证：🔴 降级为Research Only**

---

### 5. 边界验证

#### 5.1 Judgment边界
- [ ] A类Judgment必须在原典授权范围内
- [ ] B类输出只能是Guidance/Research
- [ ] C类输出只能是Framework/Methodology

#### 5.2 L4隔离检查
- [ ] 禁止引入力量比较相关Primitive
- [ ] 禁止使用"旺衰评分"等Legacy Strength概念
- [ ] 所有涉及"势/强弱"的判断必须是RESEARCH_ONLY

### 6. 审计检查

- [ ] 审计报告必须标注：
  - 原文定位
  - 术语对齐情况
  - A/B/C分类验证

## 使用示例

### 示例1：DTS-GEJU-001（失败案例重审）

**原典原文**：
> "旺则宜泄宜伤，衰则喜帮喜助"

**声称断言**：
- Primitive: 月令主气为正官
- Composite: 得令 + 透干 + 生扶 → 成格

**核验结果**：
- [x] 原文核验：通过
- [ ] 术语对齐：失败（原典谈"旺衰"，不是"格局"）
- [ ] A/B/C分类：**B类**（"宜泄宜伤"是建议，不是条件判断）
- [ ] 可计算性验证：跳过（B类不需验证）
- [x] 边界验证：失败（"成格"超出原典范围）

**结论**：🔴 **DENIED**

**正确解读**：
- 这条是B类（建议性原则）
- 只能形成GuidanceAtom："旺时宜泄伤"
- 不能形成Production Judgment："旺→成格"
- 不能进入Step 2

---

### 示例2：假设的A类语句

**原典原文**：
> "五阳从气不从势，五阴从势无情义"

**声称断言**：
- Primitive: 日主为五阳之一
- Condition: 四柱阳气盛
- Judgment: 从气不从势

**核验结果**：
- [x] 原文核验：通过
- [x] 术语对齐：通过（"从气不从势"直接引用）
- [x] A/B/C分类：**A类**（明确的判断）
- [x] 可计算性验证：
  - [x] 输入明确：日主为五阳、四柱阳气盛
  - [x] 输出明确：从气不从势
  - [x] 工程可行：不涉及L4力量问题
- [x] 边界验证：通过（Judgment在原典范围内）

**结论**：🟢 **APPROVED**

**处理**：
- 可以进入Step 2 Primitive提取
- 可以形成Production Primitive
- 可以形成Condition
- 可以形成Judgment
