>

## 逐条审计结果

### DTS-GEJU-001: 月令透干成格

#### 声称断言
- Primitive: 月令主气为正官
- Composite: 得令 + 透干 + 生扶 → 成格

#### 原文核验

| 核验项 | 原典是否支持 | 证据 |
|--------|-------------|------|
| "月令主气"概念 | ⚠️ 部分支持 | 原典谈"得令"，但未明确定义"月令主气"术语 |
| "天干透出"概念 | ⚠️ 部分支持 | 原典谈"透出"在别处，但衰旺篇未明确讨论 |
| "得令+透干+生扶→成格" | 🔴 **不支持** | 原典说的是"旺则宜泄宜伤"，不是"成格条件" |

#### 关键问题

1. **术语错误**：原典谈的是"旺衰"（强度判断），不是"格局"（结构判断）
2. **逻辑跳跃**：原典说"旺则宜泄宜伤"（如何处理旺），不是"旺则成格"（旺必然成格）
3. **混淆概念**："成格"是子平真诠体系的概念，滴天髓通神论未讨论此概念

#### 结论: 🔴 **DENIED**

**理由**: 
- Evidence不成立（原典未授权"成格"概念）
- Primitive语义扩大（将"旺衰判断"等同于"格局判定"）
- Composite无原典依据（"得令+透干+生扶→成格"是工程推断）
- Judgment越界（原典没说"成格"）

## 核心发现总结

### 1. 术语混淆问题
**原典谈的是"旺衰"（强度判断），不是"格局"（结构判定）**

- "得令、得地、得势"是强度评估框架
- "成格"是子平真诠体系的概念
- 将两者混用导致语义漂移

### 2. 逻辑跳跃问题
**原典说"如何处理"，没说"必然结果"**

- 原典："旺则宜泄宜伤"（建议如何处理）
- 工程推断："旺则成格"（必然判断）
- 这是从"宜"到"必然"的逻辑跳跃

### 3. L4力量风险
**DTS-GEJU-005涉及已删除的Strength计算**

- `KE_XIE_HAO_DOMINANT`本质是力量比较
- V1.4基线已删除Legacy Strength
- 重新引入会破坏隔离

### 4. 方法论问题
**"先写代码，再找原典背书"的危险**

- 第一批的代码是先有程序结构
- 然后找原典给程序结构背书
- 这正好是GPT裁决4762e19警告的问题

## 下一步建议

### 必须纠正的问题

1. **停止"先写代码，再找原典背书"的模式**
   - 必须先有原典核验，再决定什么进入生产
   - 宁可100条高可信，不要1000条无法核验

2. **严格区分"强度判断"和"格局判定"**
   - 滴天髓通神论主要讨论旺衰（强度）
   - 格局判定是另一套体系（子平真诠）
   - 不能混淆两个体系的概念

3. **不引入L4力量问题**
   - DTS-GEJU-005涉及的`KE_XIE_HAO_DOMINANT`必须标注为RESEARCH_ONLY
   - 等待力量评估体系完成后再考虑

### 重建规范（基于GPT裁决4762e19）

新规范必须包含：
```
原典原文 → 语义单元 → Primitive → 原典明确关系 → Condition → Judgment
```

如果找不到：
```
原典说"A且B且C，因此D"
```
那么：
```
D就不能作为生产Judgment
```
