## 核心原则（GPT裁决9b6f97e）

### 原则1：Primitive必须来自原典
**禁止**现代工程概念硬塞进古籍，然后声称"原典支持"。

### 原则2：禁止"描述→判定"的逻辑跳跃
这是上一批5条失败的根本原因。

### 原则3：区分两种原典关系

#### A类：原典明确条件→结论
```
格式："若A，则B" / "A则B" / "A者B也"
示例："甲木生于春...则气旺"
性质：明确的逻辑判断
处理：可以形成Production Judgment
```

#### B类：原典描述/原则
```
格式："A宜B" / "A喜B" / "A忌B" / "A者B之象"
示例："旺则宜泄宜伤" / "衰则喜帮喜助"
性质：描述性或建议性陈述
处理：只能形成Evidence/GuidanceAtom/Research，不能自动变成"A→B"
```

### 原则4：原典决定可计算性
不能由Schema决定什么可计算，必须由原典决定。

## 核验流程（v2.0）

```
原典原文 → 语义单元 → Primitive → A/B分类 → 授权验证 → Condition → Judgment
   ↓          ↓          ↓         ↓         ↓          ↓         ↓
权威来源   提取关键概念 术语对齐   明确判断   必须有    验证       边界验证
                    （禁止混用） （区分A/B） （仅A类）
```

## 核验清单

### 1. 原文核验

#### 1.1 来源权威性
- [ ] 使用通行本权威来源（任铁樵《滴天髓阐微》）
- [ ] 标注来源URL或书籍版本
- [ ] 至少有两个独立来源交叉验证

**来源优先级**：
1. 中国哲学书电子化计划 (ctext.org)
2. 通行本纸质书籍（任铁樵注本）
3. 学术机构整理的权威版本

**禁止使用**：
- 个人博客解读
- AI生成的paraphrase
- 未经核实的网络转载

#### 1.2 原文完整性
- [ ] 提取完整段落（非断章取义）
- [ ] 标注章节位置（如"通神论·衰旺篇"）
- [ ] 包含任铁樵注释（如有）

#### 1.3 文本分层
- [ ] 区分：原文 / 任注 / 后世解释
- [ ] 标注：ORIGINAL_TEXT / ORIGINAL_COMMENTARY / LATER_COMMENTARY
- [ ] 禁止将后世解释当作原文使用

---

### 2. 语义单元提取

#### 2.1 术语来源
- [ ] 每个Primitive术语必须有原典出处
- [ ] 标注术语在原文中的具体位置
- [ ] 禁止使用现代工程术语替代原典术语

**示例**：
- ✅ "得令"（原典术语）
- ❌ "MONTH_LENG_TRANSPARENT"（工程术语）

#### 2.2 术语对齐
- [ ] Primitive术语与原典术语一致
- [ ] 禁止混用不同体系术语
- [ ] 禁止将"旺衰"概念等同于"格局"概念

**关键检查**：
```
原典谈的是：旺衰（强度判断）
工程化成了：格局（结构判定）
→ 这是语义漂移！
```

---

### 3. A/B分类验证（v2.0新增）

#### 3.1 判断类型识别
对每个原典语句，必须分类：

**A类：明确条件→结论**
- [ ] 找到明确的逻辑连接词（若/则/者...也）
- [ ] 找到明确的推导关系
- [ ] 判断具有确定性（不是建议性）

**B类：描述/原则/建议**
- [ ] 识别为建议性表述（宜/喜/忌/当/须）
- [ ] 识别为描述性表述（者...也/之谓也）
- [ ] 识别为原则性表述（总不外/总归于）

#### 3.2 处理规则
- [ ] **A类语句**：可以进入Condition/Judgment
- [ ] **B类语句**：只能进入Evidence/GuidanceAtom/Research
- [ ] **禁止**将B类语句自动升级为A类判断

**示例对比**：
```
A类：「甲木生于寅卯月...则气旺」
   → 可以形成Production Judgment

B类：「旺则宜泄宜伤」
   → 只能形成Research Guidance
   → 不能自动变成「旺→成格」
```

---

### 4. 逻辑授权验证

#### 4.1 条件判断授权
- [ ] **如果是A类语句**：找到原典的条件判断语句
- [ ] **如果是B类语句**：确认只作为Evidence/Guidance
- [ ] 禁止从B类语句推断A类判断

#### 4.2 禁止的推断模式
- [ ] 禁止从"宜"升级为"必然"
- [ ] 禁止从"描述"升级为"判定"
- [ ] 禁止从"可能性"升级为"确定性"
- [ ] 禁止将B类建议自动变成A类条件判断

**检查模板**：
```
原典说：A情况下"宜"B（B类）
工程推断：A → 必然B（A类）

这是逻辑跳跃！🔴
```

---

### 5. 边界验证

#### 5.1 Judgment边界
- [ ] A类Judgment必须在原典授权范围内
- [ ] B类输出只能是Guidance/Research
- [ ] 禁止超出原典范围的判断

#### 5.2 L4隔离检查
- [ ] 禁止引入力量比较相关Primitive
- [ ] 禁止使用"旺衰评分"等Legacy Strength概念
- [ ] 所有涉及"势/强弱"的判断必须是RESEARCH_ONLY

**高风险术语**：
- KE_XIE_HAO_DOMINANT（克泄耗占主导）
- WANG_SHUAI_SCORE（旺衰评分）
- DE_SHI_PAN_DUAN（得势判断）

## 使用示例

### 示例1：DTS-GEJU-001（失败案例重审）

**原典原文**：
> "旺则宜泄宜伤，衰则喜帮喜助"

**声称断言**：
- Primitive: 月令主气为正官
- Composite: 得令 + 透干 + 生扶 → 成格

**核验结果**：
- [x] 原文核验：通过
- [ ] 术语对齐：失败（原典谈"旺衰"，不是"格局"）
- [ ] A/B分类：**B类语句**（"宜泄宜伤"是建议，不是条件判断）
- [ ] 逻辑授权：失败（B类不能形成"A→B"判断）
- [x] 边界验证：失败（"成格"超出原典范围）

**结论**：🔴 **DENIED**

**正确解读**：
- 这条是B类（建议性原则）
- 只能形成GuidanceAtom："旺时宜泄伤"
- 不能形成Production Judgment："旺→成格"

---

### 示例2：假设有A类原典语句

**原典原文**：
> "五阳从气不从势，五阴从势无情义"

**声称断言**：
- Primitive: 日主为五阳之一
- Condition: 四柱阳气盛
- Judgment: 从气不从势

**核验结果**：
- [x] 原文核验：通过
- [x] 术语对齐：通过（"从气不从势"直接引用）
- [x] A/B分类：**A类语句**（明确的判断"从气不从势"）
- [x] 逻辑授权：通过（原典明确条件判断）
- [x] 边界验证：通过（Judgment在原典范围内）

**结论**：🟢 **APPROVED**
