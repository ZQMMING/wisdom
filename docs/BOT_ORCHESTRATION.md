## 三、工作流

### 3.1 任务派发流程

```text
用户指令
    ↓
Hermes 解析意图
    ↓
识别目标引擎 / 任务类型
    ↓
【调度决策】
├── 纯代码修复 → it BOT
├── 引擎审计 → 对应引擎 BOT
├── 证据溯源 → ziliao BOT
├── 跨引擎协调 → Hermes 直接处理
└── 架构变更 → 用户拍板
    ↓
创建任务分支（工程化）
    ↓
执行任务
    ↓
运行测试验证
    ↓
生成审核报告
    ↓
用户审核确认
    ↓
合并到 main
```

### 3.2 任务类型矩阵

| 任务类型 | 负责 BOT | 示例 |
|---------|---------|------|
| **Calculation Integrity Audit** | 对应引擎 BOT | 四柱计算、节气边界、时柱推导 |
| **Evidence Verification** | ziliao BOT | 原典出处核验、VERIFIED 标记 |
| **Bug Fix** | it BOT | 代码修正、测试修复、回归验证 |
| **Architecture Audit** | 对应引擎 BOT + Hermes 审核 | 引擎边界、数据链路、越权检查 |
| **Cross-Engine Coordination** | Hermes 直接调度 | 五引擎一致性、接口对齐 |
| **Test Expansion** | it BOT | 新增测试用例、Golden Dataset |
| **Documentation** | Hermes 汇总 | 审计报告、状态文档 |

## 四、分支管理规范

### 4.1 分支命名规则

```
{engine}-{phase}-{task}
├── engine: ziping | mangpai | ziwei | heluo | yi | ziliao | it
├── phase:  P0 | P1 | P2 | ... | P6
└── task:   AUDIT | FIX | VERIFY | EXPAND | ...
```

**示例：**
- `ziping-P2-AUDIT` — 子平引擎 P2 阶段审计
- `it-P2-FIX-001` — IT BOT P2 阶段第 1 个修复任务
- `ziliao-P1-VERIFY` — 资料 BOT P1 阶段验证

### 4.2 分支生命周期

```
创建分支 → 开发/审计 → 测试验证 → 生成报告 → 用户审核 → 合并 main → 删除分支
```

### 4.3 提交规范

```
{phase}-{type}: {描述}

示例：
P2.3-PHYS: Fix positional filter bug in calc_day_branch_clash/harm
P6.4-AUDIT: Zǐpíng Calculation Integrity Audit — Four Pillars + Time Boundary
it-P2-FIX: 修复 test_canonical_bazi_dataset_expansion.py 测试失败
```

## 五、审核机制

### 5.1 自动化审核清单

每个 BOT 完成任务后必须通过：

| 审核项 | 说明 | 检查方式 |
|-------|------|---------|
| **测试通过** | 相关测试套件 100% PASS | pytest |
| **无 new failures** | 不引入新失败测试 | 对比基线 |
| **边界清晰** | 算→辨→解 三层隔离 | 代码审查 |
| **证据可溯源** | 所有结论有原典依据 | ziliao 核验 |
| **性能无退化** | 测试时间不增加 | pytest -q |

### 5.2 人工审核清单

Hermes 生成审核报告后，用户确认：

- [ ] 任务目标已完成
- [ ] 测试全部通过
- [ ] 无越权行为（算→辨→解分层）
- [ ] 证据链条完整
- [ ] 可以合并到 main

### 5.3 冲突处理

```
检测到冲突（如多个 BOT 修改同一文件）
    ↓
Hermes 暂停调度
    ↓
用户决策：
  ├── 优先级排序 → 顺序执行
  ├── 并行策略 → 不同子模块
  └── 架构调整 → 修改分工
    ↓
重新派发任务
```

## 七、Hermes 调度规则

### 7.1 调度优先级

```
1. 紧急修复（bug、测试失败）→ it BOT
2. 审计任务（引擎验证）→ 对应引擎 BOT
3. 证据溯源（verification）→ ziliao BOT
4. 架构变更 → 用户决策
```

### 7.2 并行规则

- ✅ 不同引擎的审计可以并行
- ✅ 测试修复可以并行
- ❌ 同一文件的修改不能并行
- ❌ 跨引擎接口的修改需协调

### 7.3 暂停规则

出现以下情况暂停调度：
- 测试套件有未解决的失败
- 分支状态不一致（本地 vs 远端）
- 用户未完成审核
- 检测到潜在数据污染
