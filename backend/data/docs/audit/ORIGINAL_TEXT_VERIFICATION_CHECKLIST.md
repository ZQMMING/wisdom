# 原典重建核验清单模板 v1.0

**版本**: 1.0  
**依据**: GPT裁决 eb69368  
**用途**: 确保所有断言在进入生产前通过严格核验

---

## 核验流程

```
原典原文 → 语义单元 → Primitive → 原典明确关系 → Condition → Judgment
   ↓          ↓          ↓            ↓           ↓         ↓
权威来源   提取关键概念 术语对齐检查  授权验证    条件验证  边界验证
```

---

## 核验清单

### 1. 原文核验

#### 1.1 来源权威性
- [ ] 使用通行本权威来源（任铁樵《滴天髓阐微》）
- [ ] 标注来源URL或书籍版本
- [ ] 至少有两个独立来源交叉验证

**来源优先级**：
1. 中国哲学书电子化计划 (ctext.org)
2. 通行本纸质书籍（任铁樵注本）
3. 学术机构整理的权威版本

**禁止使用**：
- 个人博客解读
- AI生成的paraphrase
- 未经核实的网络转载

#### 1.2 原文完整性
- [ ] 提取完整段落（非断章取义）
- [ ] 标注章节位置（如"通神论·衰旺篇"）
- [ ] 包含任铁樵注释（如有）

#### 1.3 文本分层
- [ ] 区分：原文 / 任注 / 后世解释
- [ ] 标注：ORIGINAL_TEXT / ORIGINAL_COMMENTARY / LATER_COMMENTARY
- [ ] 禁止将后世解释当作原文使用

---

### 2. 语义单元提取

#### 2.1 术语来源
- [ ] 每个Primitive术语必须有原典出处
- [ ] 标注术语在原文中的具体位置
- [ ] 禁止使用现代工程术语替代原典术语

**示例**：
- ✅ "得令"（原典术语）
- ❌ "MONTH_LENG_TRANSPARENT"（工程术语）

#### 2.2 术语对齐
- [ ] Primitive术语与原典术语一致
- [ ] 禁止混用不同体系术语
- [ ] 禁止将"旺衰"概念等同于"格局"概念

**关键检查**：
```
原典谈的是：旺衰（强度判断）
工程化成了：格局（结构判定）
→ 这是语义漂移！
```

---

### 3. 逻辑授权验证

#### 3.1 条件判断授权
- [ ] 找到原典的条件判断语句（如"若...则..."）
- [ ] 证明AND/OR/SEQUENCE由原典明确授权
- [ ] 禁止从"描述现象"推断"必然判断"

**检查模板**：
```
原典说：A情况下"宜"B
工程推断：A → 必然B

这是逻辑跳跃！
```

#### 3.2 禁止的推断模式
- [ ] 禁止从"宜"升级为"必然"
- [ ] 禁止从"描述"升级为"判定"
- [ ] 禁止从"可能性"升级为"确定性"

**示例**：
- ✅ 原典："旺则宜泄"
- ❌ 工程："旺 → 成格"
- ❌ 这是从"宜"到"必然"的非法推断

---

### 4. 边界验证

#### 4.1 Judgment边界
- [ ] Judgment必须在原典授权范围内
- [ ] 禁止超出原典描述的判断
- [ ] 标注每个Judgment的原文依据

#### 4.2 L4隔离检查
- [ ] 禁止引入力量比较相关Primitive
- [ ] 禁止使用"旺衰评分"等Legacy Strength概念
- [ ] 所有涉及"势/强弱"的判断必须是RESEARCH_ONLY

**高风险术语**：
- KE_XIE_HAO_DOMINANT（克泄耗占主导）
- WANG_SHUAI_SCORE（旺衰评分）
- DE_SHI_PAN_DUAN（得势判断）

---

### 5. 审计检查

#### 5.1 Claude独立审计
- [ ] 由Claude进行独立语义审计
- [ ] 审计报告必须标注：
  - 原文定位
  - 术语对齐情况
  - 逻辑授权情况
  - 边界越界情况

#### 5.2 GPT最终裁决
- [ ] 提交GPT进行最终裁决
- [ ] 裁决必须明确：
  - 是否通过核验
  - 是否可以进入生产
  - 哪些条件必须满足

## 核验结果分类

### 通过（APPROVED）
- [ ] 原文核验通过
- [ ] 术语对齐通过
- [ ] 逻辑授权通过
- [ ] 边界验证通过
- [ ] Claude审计通过
- [ ] GPT裁决通过

**状态**: 可以进入Production

### 有条件通过（APPROVED_WITH_NOTES）
- [ ] 大部分通过
- [ ] 但有部分需要补充核验
- [ ] 明确标注待补充项

**状态**: 补充核验后重新申请

### 拒绝（DENIED）
- [ ] 原文核验不通过
- [ ] 或术语对齐不通过
- [ ] 或逻辑授权不通过
- [ ] 或边界验证不通过

**状态**: 降级为RESEARCH_ONLY，禁止进入Production

## 使用示例

### 示例1：DTS-GEJU-001（失败案例）

**原典原文**：
> "旺则宜泄宜伤，衰则喜帮喜助"

**声称断言**：
- Primitive: 月令主气为正官
- Composite: 得令 + 透干 + 生扶 → 成格

**核验结果**：
- [x] 原文核验：通过（确实在通神论·衰旺篇）
- [ ] 术语对齐：失败（原典谈"旺衰"，不是"格局"）
- [ ] 逻辑授权：失败（原典说"宜泄宜伤"，没说"成格"）
- [x] 边界验证：失败（"成格"超出原典范围）

**结论**：🔴 DENIED

---

### 示例2：假设有某条断言通过核验

**原典原文**：
> "五阳从气不从势，五阴从势无情义"

**声称断言**：
- Primitive: 日主为五阳之一
- Condition: 四柱阳气盛
- Judgment: 从气不从势

**核验结果**：
- [x] 原文核验：通过
- [x] 术语对齐：通过（"从气不从势"直接引用）
- [x] 逻辑授权：通过（原典明确条件判断）
- [x] 边界验证：通过（Judgment在原典范围内）

**结论**：🟢 APPROVED
