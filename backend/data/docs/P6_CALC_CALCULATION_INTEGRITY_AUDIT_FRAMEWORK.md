## 一、审计原则

1. **FROZEN≠PROVEN CORRECT**：代码冻结不等于计算正确
2. **算准→辨准→解准**：算层是整个项目的地基，算错则全错
3. **可复现性**：相同输入必须产生相同输出
4. **可追溯性**：每个计算结果必须能追溯到原始输入和计算规则
5. **原典授权**：计算规则必须有原典或传统主流体系授权，禁止自行发明

## 五、审计方法

### 5.1 黄金用例测试

建立一组**黄金用例**（Golden Cases），每个用例包含：
- 输入：出生时间（公历年月日时分）、性别、出生地
- 期望输出：四柱、藏干、十神、十二长生等
- 验证方式：自动比对实际输出与期望输出

**黄金用例来源**：
1. 传统命理书籍中的已知命例
2. 在线排盘工具交叉验证（3个以上工具一致）
3. 原典中的命例（如《滴天髓》任铁樵批命例）

### 5.2 边界测试

重点测试边界情况：
- 立春前后（年柱切换）
- 每月节令前后（月柱切换）
- 子时交接（23:00-01:00，日柱切换）
- 节气交接时刻（精确到分钟）
- 闰月处理

### 5.3 交叉验证

- 与3个以上在线排盘工具交叉验证
- 与传统命理书籍中的命例交叉验证
- 与原典中的命例交叉验证

### 5.4 代码审查

- 计算逻辑代码审查
- 固定表数据审查
- 边界条件处理审查
- 异常处理审查

## 八、与辨证层的关系

**重要原则**：算层审计不通过，辨证层结果不可信。

```
算层（Calculation）
    ↓ 必须100%正确
Canonical Facts / Relations
    ↓
辨证层（Discrimination）
    ↓
解层（Assertion）
```

当前辨证层工作（P0-2.9-E/F）正在推进，但算层完整性审计（P6-CALC）仍是最高优先级。
辨证层的所有结果都依赖算层的正确性，因此算层审计必须持续进行。
