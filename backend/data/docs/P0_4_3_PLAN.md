# P0-4.3 工作计划：五经规则语义类型研究

**目标**: 建立五经原典论断的语义类型体系，为 Condition DSL 设计提供语义基础

---

## 一、背景

P0-4.2 结论：
- 4 条 Primitive 找到上下文 3/4（75%）
- 语义状态全部 UNKNOWN
- **证据不足 ≠ 规则成立**

核心发现：
> 原典文字 → AND/OR/BLOCKING 不是五经本身明确提供的机器逻辑

现在遇到的是 **ontology / semantics 问题**，不是代码问题。

---

## 二、语义类型体系

建议分类（待 GPT 裁决）：

| 类型 | 定义 | 示例 | 可能映射 |
|------|------|------|---------|
| ① 事实/状态 | 描述客观状态 | "甲木参天" | Feature |
| ② 条件 | 明确条件关系 | "若...则..." | Condition |
| ③ 充分条件 | 满足即成立 | "...则贵" | SUPPORTING |
| ④ 必要条件 | 必须满足 | "须..." | PREREQUISITE |
| ⑤ 倾向/宜忌 | 推荐或忌讳 | "宜损之" | OPTIONAL |
| ⑥ 制约/阻断 | 阻止或限制 | "不可犯" | BLOCKING |
| ⑦ 推论 | 从前提推出的结论 | "故..." | 待定 |
| ⑧ 复合论断 | 多个条件组合 | "...且..." | AND/OR |
| ⑨ 未确定 | 无法判断语义 | - | UNKNOWN |

---

## 三、研究方法

### Phase 1: 建立分类标准
1. 定义每种语义类型的判断标准
2. 给出明确的原文示例
3. 说明与 Feature/Condition 的映射关系

### Phase 2: 抽样验证
1. 从五经中抽取 50-100 条论断
2. 逐条分类
3. 统计分布

### Phase 3: 映射到 DSL
1. 确认哪些类型可以映射到 AND/OR/BLOCKING
2. 哪些保持 UNKNOWN
3. 设计 Condition DSL 的结构

---

## 四、禁止事项

❌ 不要为了分类而强行解释原典  
❌ 不要假设原典有 AND/OR 逻辑  
❌ 不要跳过语义分析直接写代码  
❌ 不要提高"通过数"而降低标准

---

## 五、成功标准

✅ 语义类型体系有明确定义  
✅ 每种类型有原文示例  
✅ 抽样验证显示分布合理  
✅ 映射到 DSL 的逻辑清晰  
✅ UNKNOWN 类型保持保守
