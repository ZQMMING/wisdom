## 一、十二长生表 — 重大发现

### 1.1 差异分布

**20 个差异全部集中在丁（DING）和己（JI）两个阴干上**，每个阴干 10 个差异（卯和酉碰巧一致）。

阳干（甲丙戊庚壬）和阴干乙、辛、癸在两套表中完全一致。

### 1.2 具体差异（以丁为例）

| 地支 | bazi_l1_facts.py（错误） | bazi_fixed_tables.py（正确） |
|------|--------------------------|-------------------------------|
| 子(ZI) | 临官 | **绝** |
| 丑(CHOU) | 帝旺 | **墓** |
| 寅(YIN) | 衰 | **死** |
| 卯(MAO) | 病 | 病 ✓（碰巧一致） |
| 辰(CHEN) | 死 | **衰** |
| 巳(SI) | 墓 | **帝旺** |
| 午(WU) | 绝 | **临官** |
| 未(WEI) | 胎 | **冠带** |
| 申(SHEN) | 养 | **沐浴** |
| 酉(YOU) | 长生 | 长生 ✓（碰巧一致） |
| 戌(XU) | 沐浴 | **养** |
| 亥(HAI) | 冠带 | **胎** |

己（JI）与丁（DING）完全相同，也是同样的 10 个错误。

### 1.3 错误原因分析

**正确的阴干逆行规则**：
- 丁长生在酉，然后**逆布**（申→未→午→巳→辰→卯→寅→丑→子→亥→戌）
- 正确顺序：酉=长生，申=沐浴，未=冠带，午=临官，巳=帝旺，辰=衰，卯=病，寅=死，丑=墓，子=绝，亥=胎，戌=养

**bazi_l1_facts.py 的错误**：
- 丁在子=临官、丑=帝旺、寅=衰... 这看起来像是**把丁当成了阳干顺行**，或者用了错误的起始点
- 实际上 bazi_l1_facts.py 的丁干数据是：子=临官，丑=帝旺，寅=衰，卯=病，辰=死，巳=墓，午=绝，未=胎，申=养，酉=长生，戌=沐浴，亥=冠带
- 这相当于把"长生在酉"然后**顺布**（戌→亥→子→丑→寅→卯→辰→巳→午→未→申），而不是逆布
- 阴干应该逆布，不是顺布

### 1.4 影响评估

**严重程度：🔴 高**

- `bazi_l1_facts.py` 是 P6.1-A 的核心成果，定位为"L1 原始事实数据"
- 丁和己两个天干的十二长生状态全部错误（除了卯和酉碰巧对）
- 所有使用 `bazi_l1_facts.py` 计算丁日或己日命例的十二长生状态都会出错
- 1983 命例是乙木日主，不受影响；但丁日、己日命例会受影响

### 1.5 裁决

- **正确数据源**：`reasoning/bazi_fixed_tables.py` 的 `LONGHU_STAGE`
- **错误数据源**：`engines/bazi_l1_facts.py` 的 `TIAN_GAN_TWELVE_GROWTH`（丁和己部分）
- **处理建议**：以 `bazi_fixed_tables.py` 为准，修正 `bazi_l1_facts.py` 的丁和己部分
- **但当前不修正**：按 P0 执行约束，先完成全量审计，再统一重构

## 二、藏干表 — 结构差异，数据一致

### 2.1 差异说明

12 个地支全部显示差异，但**实际藏干内容是一致的，只是数据结构不同**。

### 2.2 结构对比

### 2.4 裁决

- **处理建议**：统一数据结构，但不改变数据内容

## 五、重要发现与启示

### 5.1 最重大发现

**P6.1-A 的核心成果 `bazi_l1_facts.py` 存在 20 个十二长生数据错误（丁和己）。**

这证明了：
1. **"FROZEN ≠ PROVEN CORRECT"** — P6.1-A 虽然标记为完成并冻结，但数据本身有错误
2. **"先审计、再重构"是正确的** — 如果没有这次 Source Reconciliation，直接用 `bazi_l1_facts.py` 建 Canonical State，丁日和己日命例的十二长生状态会全部错误
3. **GitHub 开源库作为 implementation source 是有风险的** — `bazi_l1_facts.py` 的数据来源是 `freddylamlc/bazi-patterns`，这个开源库的丁和己十二长生表可能本身就是错的

### 5.2 数据源统一的方向

基于本次审计：
- **十二长生表**：以 `bazi_fixed_tables.py` 的 `LONGHU_STAGE` 为准
- **藏干表**：数据内容一致，统一结构即可
- **十神计算**：完全一致，统一为一套实现即可

但这只是**工程一致性**的结论，**原典认证**还需要进一步验证：
- 阳顺阴逆、火土同生的体系是否符合五部经典原典？
- 藏干的本气/中气/余气分层是否符合原典？
- 十神的定义是否符合原典？

这些都属于 **SOURCE_RECONCILIATION 的下一阶段**，当前只完成了工程一致性审计。
